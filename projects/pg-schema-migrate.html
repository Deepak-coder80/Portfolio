pg-schema-migrate

Transfers PostgreSQL database structure - tables, indexes, constraints, functions, views - between hosts without touching data. Auto-backup, rollback scripts, and dry-run included. Two modes: direct migration or export for manual review.

GitHub → Releases Issues

Why this exists

When you need to sync a database structure - not data - between environments, the existing tools are either overkill (full migration frameworks) or too low-level (raw pg_dump flags). This fills the gap: schema-only, safe, with rollback built in.

Schema-only safety

  • Transfers structure, never touches row data
  • Zero risk of production data leaking to staging
  • Perfect for environment bootstrapping

Two migration modes

  • Direct: connects both hosts, migrates immediately
  • Export: generates SQL files for manual review
  • Rollback scripts generated automatically

Production safe

  • Dry-run previews all changes before execution
  • Auto-backup of destination before any changes
  • SSL support for encrypted production connections

Features

◎

Schema-only

Tables, indexes, constraints, functions, views, triggers - no data rows.

⟳

Two modes

Direct migration or export to SQL files. Pick based on your review process.

△

Auto backups

Backs up the destination schema before touching anything. Rollback script generated.

⬡

Dry-run mode

Preview the full migration plan before a single SQL statement executes.

◈

SSL support

All PostgreSQL SSL modes supported for secure production connections.

○

Role migration

Optionally include database roles and permissions in the migration.

Installation

Linux / macOS
wget https://github.com/Deepak-coder80/pg-schema-migrate/releases/latest/download/pg-schema-migrate-linux chmod +x pg-schema-migrate-linux sudo mv pg-schema-migrate-linux /usr/local/bin/pg-schema-migrate
Prerequisites
# Ubuntu / Debian sudo apt-get install postgresql-client # macOS brew install postgresql pg_dump --version # verify

Usage

Direct migration (prod → staging)
pg-schema-migrate \ --source-host prod-db.example.com \ --source-user myuser \ --source-db myapp_prod \ --dest-host staging-db.example.com \ --dest-user myuser \ --dest-db myapp_staging
Export mode (review before applying)
pg-schema-migrate \ --mode export \ --source-host prod-db.example.com \ --source-user myuser \ --source-db myapp_prod \ --output-dir ./schema_export
Dry run (preview only)
pg-schema-migrate \ --source-host localhost \ --source-db myapp_dev \ --dest-db myapp_test \ --dry-run
Generated file structure
schema_migration/ ├── schema_mydb_20240806_143022.sql # Exported schema ├── rollback.sh # Auto-generated rollback └── backup/ └── backup_mydb_20240806_143022.sql
Rollback if needed
cd schema_migration ./rollback.sh

How it works

Built with Go

Wraps pg_dump with schema-only flags, handles connection management, and orchestrates the backup-migrate-verify sequence.

Safety architecture

Direct mode always backs up the destination first. The backup file and rollback script are generated before any schema changes are applied.

Two-mode design

Direct mode for automated pipelines. Export mode for teams that require DBA review before any schema changes hit the destination.

Cross-cloud ready

Works with any PostgreSQL 9.6+ host - AWS RDS, GCP Cloud SQL, Azure Database, or self-hosted - with full SSL support.

Use pg-schema-migrate

The right tool when you need structure without data. Backup first, rollback ready, dry-run always available.
