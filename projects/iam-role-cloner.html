iam-role-cloner

Clone IAM roles between AWS environments with automated pattern replacement, dry-run validation, and full audit logging. Reduces hours of manual IAM configuration to minutes - safely.

GitHub → Releases Issues

Why this exists

Setting up a new AWS environment means recreating every IAM role with environment-specific names and policy content. Doing it manually means hours of copying, editing, and validating - with human error risk on every policy document. This tool makes it a single command with a dry-run you can review first.

Environment migration

  • Clone all dev roles to production in batch
  • Automatic pattern replacement across names, policies, tags
  • Progress tracking for large role sets

Safety first

  • Dry-run mode shows exactly what will change
  • Full audit log of every operation
  • Validates policies before creating roles

Automation ready

  • Interactive mode for manual runs
  • Full CLI flags for CI/CD pipelines
  • Pattern-based role discovery and filtering

Features

⟳

Role cloning

Clones trust policies, managed policies, inline policies, and tags - all with pattern replacement.

◎

Pattern replacement

dev_ → prod_ in role names, policy content, and tag values simultaneously.

△

Dry-run mode

Preview every change before it hits AWS. Review transformed policy documents in full.

⬡

Audit logging

Coloured terminal output plus file-based logs for compliance and incident review.

◈

Role discovery

Filter source roles by pattern - clone all roles matching "dev-" without listing each one.

○

Batch processing

Process multiple roles in one run with per-role progress tracking and error isolation.

Usage

Interactive mode (recommended first run)
./iam-role-cloner clone ./iam-role-cloner clone --dry-run --verbose
Automated clone - dev to prod
./iam-role-cloner clone \ --source-profile development \ --dest-profile production \ --source-pattern "dev-" \ --dest-pattern "prod-"
What gets cloned
Trust policies (assume role) - with pattern replacement Managed policies (AWS + customer managed) Inline policies - with pattern replacement in content Tags - with pattern replacement and environment metadata Role description - with clone audit metadata appended
Required IAM permissions
{ "Action": [ "iam:GetRole", "iam:CreateRole", "iam:ListRoles", "iam:ListAttachedRolePolicies", "iam:ListRolePolicies", "iam:GetRolePolicy", "iam:AttachRolePolicy", "iam:PutRolePolicy", "iam:TagRole", "iam:ListRoleTags" ] }

How it works

Built with Go + AWS SDK v2

Native IAM API calls - GetRole, CreateRole, policy management, and tag operations with proper pagination for large role sets.

Pattern processing engine

Replaces the source pattern across role names, policy document content, trust relationships, and tag values - while maintaining JSON validity.

Dry-run architecture

Every operation is computed and logged before execution. You see the full transformed policy document before a single API call is made.

Error isolation

Failures on individual roles don't halt the batch. Each role result is logged independently so you know exactly what succeeded and what to retry.

Use iam-role-cloner

Stop recreating IAM roles by hand when setting up new AWS environments. One command, dry-run first, full audit log.
