env_factory

Unified environment configuration for Python apps. One interface for local .env files and AWS Secrets Manager - switch between them with a single parameter. Full type safety, case-insensitive key matching, and error recovery.

PyPI → GitHub Issues

Why this exists

Python apps typically use os.environ or python-dotenv in development, then bolt on AWS Secrets Manager for production with completely different code paths. env_factory gives you one interface for both, so the only thing that changes between environments is a source parameter.

Multi-source config

  • Local .env for development, AWS SM for production
  • Switch with a single parameter - no code changes
  • Factory pattern for clean source abstraction

Developer experience

  • Full type hints throughout
  • Case-insensitive key matching with fallback
  • Debug and warning logs for troubleshooting

Production reliability

  • Continues processing if some keys are missing
  • Meaningful error classes for each failure mode
  • Tested with Django, FastAPI, Flask

Features

⟳

Dual source

Local .env and AWS Secrets Manager in one interface. One function call, two backends.

⬡

Type safety

Full type hints, typed return values, and explicit error classes for each failure mode.

◎

Factory pattern

Create retrievers for each source independently. Swap without changing consuming code.

△

Smart matching

Case-insensitive key lookup with fallback. Works even when key casing differs between environments.

◈

Error recovery

Returns partial results on missing keys rather than failing completely. Handle missing vars your way.

○

Framework tested

Integration examples for Django, FastAPI, and Flask. Drop-in for any Python project.

Installation

pip
pip install env-factory
.env file (required for local source)
API_KEY=my-secret-api-key DATABASE_URL=postgresql://localhost:5432/myapp AWS_ACCOUNT_ID=123456789012 # required for AWS source

Usage

Local environment variables
from dotenv import load_dotenv from env_factory import get_env_variables load_dotenv() config = get_env_variables(['API_KEY', 'DATABASE_URL']) # {'API_KEY': 'my-secret-api-key', 'DATABASE_URL': 'postgresql://...'}
AWS Secrets Manager
secrets = get_env_variables( keys=['DB_PASSWORD', 'JWT_SECRET'], source='aws', secret_name='my-app-secrets', region='us-east-1', role_name='my-app-role' )
Environment-aware configuration
import os from env_factory import get_env_variables env = os.getenv('ENVIRONMENT', 'development') if env == 'production': config = get_env_variables( keys=['DATABASE_PASSWORD', 'API_KEY'], source='aws', secret_name='prod-app-secrets', region='us-east-1', role_name='prod-secrets-role' ) else: config = get_env_variables(['DATABASE_PASSWORD', 'API_KEY'])
Error handling
from env_factory import get_env_variables, ConfigurationError, SecretRetrievalError try: variables = get_env_variables(keys=['API_KEY'], source='aws', ...) except ConfigurationError as e: print(f"Config error: {e}") except SecretRetrievalError as e: print(f"AWS retrieval failed: {e}")

How it works

Factory pattern

EnvFactory.create_local_retriever() and create_aws_retriever() return typed retriever objects. Swap the retriever, keep the calling code identical.

Type safety

Returns Dict[str, Optional[str]]. Missing keys return None rather than raising - you decide what to do with missing config.

Case-insensitive matching

Looks up keys case-insensitively with fallback strategies. Works when dev .env uses lowercase and production secrets use uppercase.

Minimal dependencies

Core package only requires python-dotenv and boto3. No transitive dependency conflicts with Django or FastAPI.
