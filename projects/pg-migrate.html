pg-migrate

Production-ready CLI for migrating PostgreSQL databases between hosts. Full schema and data preservation, SSL support, and cross-cloud compatibility. One command replaces a manual multi-step process.

GitHub → Releases Issues

Why this exists

Database migrations between hosts are painful. SSL configs differ. Cloud providers behave differently. pg_dump flags aren't obvious. This tool wraps all of that into a single interactive CLI that handles dev-to-prod, cloud-to-cloud, and cloning scenarios.

Dev to production

  • Local to AWS RDS in one command
  • Handles varying SSL requirements per environment
  • Schema-first approach prevents partial migrations

Cross-cloud migration

  • AWS RDS to GCP Cloud SQL
  • Azure Database to self-hosted
  • Any PostgreSQL 9.6+ instance

Environment sync

  • Clone prod to staging for testing
  • Share exact database state with team
  • Disaster recovery cross-region

Features

⟳

Cross-host migration

Source and destination can be on completely different servers or cloud providers.

⬡

SSL support

Works with cloud databases requiring encrypted connections - require, verify-ca, verify-full.

◎

Safe by default

Schema-first approach using pg_dump/pg_restore. No partial state.

△

Interactive prompts

Guides you through each step. Hidden password input. No credentials in shell history.

◈

Complete preservation

Migrates schema, data, indexes, constraints, triggers, and sequences.

○

Cross-platform

Pre-built binaries for Linux, macOS (Intel + Apple Silicon), and Windows.

Installation

Linux / macOS
curl -L https://github.com/Deepak-coder80/pg-migrate/releases/latest/download/pg-migrate-linux-amd64.tar.gz | tar xz sudo mv pg-migrate /usr/local/bin/
Build from source
git clone https://github.com/Deepak-coder80/pg-migrate.git cd pg-migrate make install
Docker
docker pull Deepak-coder80/pg-migrate:latest alias pg-migrate='docker run --rm -it Deepak-coder80/pg-migrate:latest'

Usage examples

Local to AWS RDS
pg-migrate \ --source-db myapp_dev \ --source-host localhost \ --source-user postgres \ --dest-host myapp.abc123.us-east-1.rds.amazonaws.com \ --dest-user postgres \ --dest-ssl require
AWS RDS to GCP Cloud SQL
pg-migrate \ --source-db production \ --source-host aws-prod.abc123.us-east-1.rds.amazonaws.com \ --source-user dbadmin \ --source-ssl require \ --dest-host gcp-prod.abc123.us-central1.sql.goog \ --dest-user postgres \ --dest-ssl verify-ca
Clone production to staging
pg-migrate \ --source-db myapp_prod \ --source-host prod.example.com \ --source-user readonly_user \ --dest-host staging.example.com \ --dest-db myapp_staging \ --dest-user postgres

How it works

Built with Go

Cross-platform compilation, fast startup. Uses Cobra for the CLI interface and industry-standard pg_dump/pg_restore under the hood.

PostgreSQL integration

Wraps pg_dump and pg_restore - compatible with all PostgreSQL 9.6+ versions including RDS, Cloud SQL, and Azure Database.

SSL handling

Supports all PostgreSQL SSL modes - disable, require, verify-ca, verify-full - with automatic configuration per host.

Secure by default

Passwords entered via hidden terminal input. No credentials stored in config files or passed as CLI flags.

Use pg-migrate

Solves the database migration problem you've been scripting around for years. MIT licensed, no dependencies beyond PostgreSQL client tools.
