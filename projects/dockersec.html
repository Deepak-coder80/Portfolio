dockersec

An offline CLI security scanner for Docker. Analyzes Dockerfiles and docker-compose files for 28 known vulnerabilities and misconfigurations — root containers, hardcoded secrets, unpinned images, missing resource limits — before anything ships to production.

GitHub → Download v0.5.0 Issues

Why this exists

Most developers write Dockerfiles by copying examples from the internet. Those examples are rarely production-safe. The mistakes are invisible until something breaks in production — or worse, until an attacker exploits them. dockersec catches them at the source, in your editor or your CI pipeline, before the code ships.

Common mistakes it catches

  • Container running as root — full host access if breached
  • API keys and passwords hardcoded in ENV instructions
  • latest image tags — silent updates, broken reproducibility
  • curl piped to bash — remote code execution risk
  • No resource limits — one bad service kills the host

How it fits your workflow

  • Run locally before committing
  • Block PRs on HIGH or CRITICAL findings in CI
  • Add custom rules without writing Go code
  • Works offline — no accounts, no data leaves the machine

Built for real projects

  • 28 rules covering Dockerfile and docker-compose
  • Every finding includes the exact line and a fix
  • Ships as a single static binary — nothing to install
  • GitHub Actions integration in one workflow step

Features

◈

28 built-in rules

20 Dockerfile rules + 8 docker-compose rules. CRITICAL, HIGH, MEDIUM, and LOW severities.

⬡

Two output formats

Full text with descriptions and fix instructions. Compact table for CI pipelines.

◎

YAML rule engine

Add custom rules without writing Go. Drop a .yml file in the rules directory, it loads automatically.

△

CI gate

--fail-on HIGH exits with code 1 if any HIGH or CRITICAL finding exists. Blocks the merge.

◻

Fully offline

Zero API calls during scanning. Works in air-gapped environments and local dev.

○

Single binary

Compiled with goreleaser for Linux, macOS (Intel + Apple Silicon), and Windows. No runtime dependencies.

Installation & usage

Install — Linux
cd /tmp curl -sSL https://github.com/Deepak-coder80/dockersec/releases/latest/download/dockersec_linux_amd64.tar.gz \ | tar -xz && sudo mv dockersec /usr/local/bin/ dockersec version # dockersec 0.5.0
Scan a project
dockersec scan .

Commonly used by attackers to create backdoors and exfiltrate data. No place in a production image. fix: | Remove netcat. How it works

Parser layer

Uses moby/buildkit — the official Docker Dockerfile parser — to build an AST. Handles all edge cases the way Docker itself would. docker-compose files parsed via YAML with typed structs.

Rule engine

Rules self-register via Go init(). Built-in rules are compiled in; YAML rules load from disk at runtime. Both run through the same execution pipeline — same output format, same severity levels.

YAML rule engine

Plugin-style architecture. Match on instruction type and string content. No rebuild required. Drop a .yml file in the rules directory — it's active on the next scan.

Distribution

goreleaser cross-compiles for Linux (amd64, arm64), macOS (Intel + Apple Silicon), and Windows in one command. GitHub Actions runs the release pipeline on every version tag.
